# Domain documentation

## Layout

Use one shared domain context for this monorepo:

- GLOSSARY.md at the repository root defines domain terms.
- docs/adr/ contains architecture decision records.

## Before exploration

Read the glossary and ADRs relevant to the task.
If a document is absent, continue without requesting its creation.
The domain-modeling skill creates documents when terms or decisions
are resolved.

## Vocabulary and decisions

Use the terms defined in the glossary.
If a required term is missing, record the gap for domain modeling.
If a proposal conflicts with an ADR, identify the conflict and explain
the proposed change.
Preserve existing ADRs.
